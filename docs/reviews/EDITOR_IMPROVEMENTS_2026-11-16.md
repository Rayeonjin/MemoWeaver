# 편집기 개선 기록 — 2026-11-16

대상은 v0.9.70 / 빌드 103입니다. `NSTextView`와 원문·미리보기 분리 구조를 유지합니다. DB 스키마, 번들 식별자, 메모·첨부 경로와 외부 라이브러리는 바꾸지 않았습니다.

## 바뀐 동작

### 긴 문서의 색상

예전에는 화면 위쪽 900 UTF-16 문자만 문맥으로 읽었습니다. 코드나 수식 블록의 시작이 그보다 멀면 본문에 Markdown 색상이 섞일 수 있었습니다. 이제 문서 앞부분에서 블록 상태를 추적하고, 화면에 보이는 줄만 인라인 구문을 분석합니다. 분석은 직렬 백그라운드 큐에서 진행하고 현재 본문·화면 요청과 일치하는 결과만 적용합니다. 조합 중인 글자와 실행 취소 내역에는 손대지 않습니다.

### 이미지 붙여넣기·드롭

클립보드 데이터는 메인 스레드에서 확보하고, 파일 읽기·이미지 변환·PNG 저장은 백그라운드에서 처리합니다. 파일 24MiB, 클립보드 표현 합계 96MiB, 최종 PNG 8MiB 및 32MP 제한을 적용합니다. 클립보드 제공자가 데이터를 생성하는 시간은 macOS 쪽에서 걸릴 수 있습니다.

삽입 시점에 메모 ID, 데이터 세대, 편집기 활성 상태, 본문 수정 번호와 한글 조합 여부를 다시 확인합니다. 처리 중 본문이 바뀌었으면 원래 위치에 억지로 넣지 않고 취소하며, 이번 요청이 만든 파일만 지웁니다. 삽입 후 실행 취소한 이미지는 다시 실행과 저장 이력에서 필요하므로 파일을 유지합니다.

### 이력 비교·복원

메모 작업 메뉴의 변경 이력에서 저장 시점을 고르면 현재 본문과 나란히 볼 수 있습니다. 복원은 본문만 바꾸며 제목·분류·기록일 등은 유지합니다. 현재 내용을 체크포인트로 저장한 뒤 일반 텍스트 교체를 실행합니다. 저장에 실패하면 복원을 진행하지 않습니다. 복원은 한 번의 실행 취소로 되돌릴 수 있습니다.

### 표 편집

표 안에 커서를 두고 오른쪽 버튼을 누르면 행·열 추가/삭제와 원문 간격 정리를 사용할 수 있습니다. 머리글·구분선 행 삭제와 2열 미만으로 줄이기는 제공하지 않습니다. 최대 24열, 본문 300행을 다룹니다. 코드·수식 블록과 표 밖까지 걸친 선택 영역은 수정하지 않습니다. 셀의 코드, 이스케이프된 파이프, 한글·이모지와 CRLF를 보존합니다.

## 검사 방법

`Tests/EditorImprovementsNativeChecks.swift`는 임시 DB와 별도 `NSTextView`를 사용합니다. 기존 네이티브 검사 묶음에 포함되어 `./install-v0.9.70.sh --verify`에서 실행됩니다. 실제 메모로 테스트하지 않습니다.

`Tests/EditorIMEPreview.swift`는 실제 한글 입력을 받을 격리 창입니다. 자동으로 조합 문자열을 만드는 검사와 달리 사용자가 입력한 marked text를 감지해야 통과 로그가 생깁니다. 전체 결과와 확인하지 못한 부분은 [확인 항목](../releases/MAC_ACCEPTANCE_v0.9.70.md)에 기록합니다.
